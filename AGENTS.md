# AGENTS.md

This is a SuiteCloud Account Customization Project (ACP) written in TypeScript and JavaScript. Read
`docs/project-structure.md`, `docs/build-pipeline.md` and `docs/library-bundler.md` for the folder
structure, build pipeline and library bundler. This file lists the rules for working in the project.

## Where to Make Changes

- Edit sources in `src/SuiteScripts/` only. `src/FileCabinet/SuiteScripts/` and `build/` are build
  output: every build overwrites them, and Git ignores them.
- If a SuiteCloud CLI command downloads JS files into `src/FileCabinet/SuiteScripts/`, move them to
  the same relative path under `src/SuiteScripts/` before editing them.
- Put SDF objects in `src/Objects/`. A script object's `scriptfile` points at the deployed JS path,
  even when the source is TypeScript: `src/SuiteScripts/RL_Echo.ts` deploys as
  `[/SuiteScripts/RL_Echo.js]`.
- Don't hand-edit `src/SuiteScripts/lib/`. Its files are generated by `npm run bundle:lib`.
- Don't edit `.agents/skills/` or `.claude/skills/`. They are vendored from
  `oracle/netsuite-suitecloud-sdk` and pinned in `skills-lock.json`.

## Verifying Changes

Fix any failure before moving on.

For smaller changes, run the lightweight checks:

```bash
npm run format:check  # Prettier
npm run lint          # ESLint
npm run check         # type check with TypeScript 7
```

For larger changes, also run the heavier checks:

```bash
npm run build         # confirms Rollup emits the AMD output
npm test              # Jest unit tests
```

Use `npm run lint:fix` or `npm run format` to fix formatting instead of hand-formatting.

Don't run `suitecloud project:deploy`, `file:upload` or any other command that writes to a NetSuite
account unless the user asks for it. `project:validate` is safe, but it still needs an authenticated
account.

## Writing TypeScript SuiteScripts

- Start every entry-point file with the `@NApiVersion 2.1` and `@NScriptType` JSDoc block, and
  leave an empty line between the block and the first line of code.
- Import `N/*` modules as default imports, for example `import log from 'N/log'`. Types come from
  `@hitc/netsuite-types`.
- Type entry points with `EntryPoints` from `N/types`.
- Export entry points as named exports. A RESTlet `delete` entry point is declared as `delete_`
  and exported with `export { delete_ as delete }`, because `delete` is a reserved word.
- Use relative imports without a file extension.
- The compiler runs in `strict` mode with `exactOptionalPropertyTypes`. Pass `undefined` explicitly
  only where a type allows it.
- The target is ES2023, which is what SuiteScript 2.1 supports. Don't use newer syntax or APIs.
- Prefer `N/*` modules and plain TypeScript over NPM packages. Suggest a new package only when it
  replaces a lot of manual implementation, as Zod does for data validation. Don't add it
  without the user's approval.
- NetSuite can't resolve NPM packages at runtime, so a suggested package must be bundled, never
  imported directly. Bundle it as described in `docs/library-bundler.md`, then import it from
  `./lib/<package>`.

## Writing JavaScript SuiteScripts

- Plain JS files must be AMD modules using `define([...], function (...) { ... })`. ESLint enforces
  the `requirejs` rules.
- To import a JS module from TypeScript, add a sibling `.d.ts` file that declares its exports. See
  `src/SuiteScripts/utils/error.js` and `src/SuiteScripts/utils/error.d.ts`.
- When converting a JS file to TypeScript, replace the `.js` file and delete its `.d.ts`, if one exists.

## Tests

Tests live in `__tests__/` and run on Jest with the SuiteCloud unit testing stubs for `N/*`
modules. Mock a module with `jest.mock('N/record')`, as `__tests__/sample-test.js` does.

## Commits

Commit messages follow Conventional Commits, and the `commit-msg` hook enforces them. The
`pre-commit` hook lints and formats staged files.
